# Rehearse ChatGPT Voice with the evidence on screen

Prepared on 20 September 2026 for the Monday meeting and the 30 September seminar.
This is a rehearsal sheet, **not a record of a successful Voice or room-audio test**.
Use public sample questions; do not enter claimant details.

## What already works

The [Monday handover](monday-handover-2026-09-21.md) contains the fixed care-home
question and its evidence replay link. The public service has passed actual
external-client and browser delivery checks. Those checks do not establish that
the presenter's ChatGPT Voice session can call the service.

There are three separate things to observe:

1. **Voice:** the app hears the question and speaks a response.
2. **Evidence access:** that session actually calls Ask OKF and receives the
   source version, context identity, records and limitations.
3. **Room presentation:** the audience can hear the response and read its sources.

A plausible spoken answer, screen reading or a successful text-mode call does
not establish all three. Remote MCP and browser WebMCP are also different access
routes; record which one was actually used.

## Five-minute desk rehearsal

1. Open the [current care-home demonstration](monday-handover-2026-09-21.md#compact-evidence-demo).
   Recreate the evidence and keep its source text, gaps and context ID visible.
2. In the ChatGPT desktop app, open the intended task and use **Start voice chat**
   if available. First-use microphone setup requires the presenter. The current
   [official Voice guide](https://learn.chatgpt.com/docs/features/voice), checked
   on 20 September, explains availability, microphone setup and the separate
   dictation feature. Do not change accounts or permissions merely to continue
   an unattended test.
3. If Ask OKF is already connected, use this instruction in the voice session:

   > Use Ask OKF for the care-home question shown in the handover. Identify the
   > exact source version and context ID, read the evidence and its gaps, then
   > explain only what that evidence supports. Keep the no-partner qualification
   > visible. If you cannot call the tool, say so rather than answering from memory.

4. Inspect an actual tool call and its returned evidence. Confirm the version,
   question and budget before comparing it with the browser package. A different
   budget can legitimately produce a different context. Follow the
   [connection guide](remote-mcp-demo.md#connect-chatgpt) if setup is needed;
   connection and Voice acceptance still need separate checks.
5. Ask the AI to identify an unanswered part, then interrupt it and ask it to
   repeat the source limitation. Stop the voice session after the rehearsal.

Do not infer tool access from a voice product name, a subscription or an appshot.
The exact call is the evidence. The service's **insufficient** status must remain
visible in the explanation. A real call still needs claim-level review; it is
not an entitlement decision.

## Room rehearsal with the presenter and AV operator

Connect the actual projector and public-address system, then deliberately select
the microphone input and sound output in the Mac's sound settings. Check the
routes again after reconnecting cables. Agree a reachable mute control and an
operator responsible for recovery. If a mixer feeds the AI microphone, keep the
AI's own output out of that feed and test for feedback.

Read a source paragraph from the back of the room. Check the AI's volume,
interruption, network delay and recovery. Keep a visible text equivalent of the
spoken response. These observations require the real room and equipment; the
agent has not changed audio settings or granted microphone access.
